## FOR UPDATE + агрегат — 2026-08-03 (PR #92, ЖИВО)

„Завеждане/Изписване" и „Брак" (non-batch пътят) бяха счупени ИЗЦЯЛО:

```
ERROR: FOR UPDATE is not allowed with aggregate functions
```

Кодът заключваше и сумираше в една заявка
(`SELECT COALESCE(SUM(quantity),0) ... FOR UPDATE`). Компилира се,
минава през mock-натите тестове, гърми при първото истинско викане.

**Правилният подход:** първо `SELECT id ... FOR UPDATE`, после отделна
сумираща заявка. Редовете вече са заключени → сумата е стабилна.
Сумирането остава в SQL (numeric) заради точността в audit snapshot-а.

⚠️ **Поука за целия проект:** unit тестовете тук мокват `db.js`, затова
НЕ хващат невалиден SQL. Добавен е статичен пазач
`src/__tests__/sql-for-update-guard.test.ts`. При нова заключваща
заявка — пусни я срещу истинска база, не се доверявай на зеления суит.

## AI Service

GQF има отделна ai-service инстанция на host port **8001**
(MERT-M / Greek Foods ползват :8000). Конфиг в
`ai-service/.env`: WAREHOUSE_API_URL=http://127.0.0.1:3005,
INTERNAL_API_KEY=devinternal_gqf_001234567890.

Стартиране:

```bash
cd ai-service
.venv311/bin/uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Endpoints: /ai/scan-invoice, /ai/quick-invoice-check,
/ai/confirm-invoice-template, /ai/match-products, /ai/forecast,
/ai/anomalies.
